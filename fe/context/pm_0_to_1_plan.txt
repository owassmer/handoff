LANDLORD–TENANT OBLIGATIONS


Earn one paid workflow.
Then repeat it.
Start in the manager’s existing systems. Build only what improves delivery.

  The goal One manager pays and renews, the work improves, and a second independent manager buys
  substantially the same offering.


01 Get access to the actual work
Build a list of 10 operators and conduct five walkthroughs. Include three operators outside personal landlord
and family connections, plus one with a smooth process.
Inspect an ordinary deposit case and an ordinary renewal/notice case. Record the trigger, completion
condition, people, systems, handling time, remaining failures, and who would pay to fix them.
  Advance when: two operators offer records and one budget owner will discuss a paid test.

02 Choose one workflow
Open with deposit closeout. Choose renewal/notice handling instead when actual cases and buying
commitment are stronger. Compare the installed software and a relevant specialist before building.
Select work that is recurring, within your control, supported by accessible records and actions, valuable to the
buyer, and reusable across operators. Do not build both workflows.
  Advance when: you can name the buyer, problem, deliverable, existing alternative, and reason to pay.

03 Sell a defined pilot
First reconstruct three authorized historical cases. Show what you would deliver, complete, and still need from
the manager. Then ask for a paid commitment.

04 Build the minimum delivery system
Create one case queue, one decision process, and one route back into existing systems. Each case shows the
facts, proposed disposition, missing information, next action, owner, deadline, and actual completion status.
Start with authorized exports, model-assisted extraction, structured rules and Python functions, approval
routing, and action tracking. Keep law, lease terms, operator policy, and case facts separate. Use focused legal
review for the live scope.
Handle both rule changes and case changes. Reuse CORDON’s method, not its entire architecture. No
general-purpose language, nationwide corpus, or replacement platform.

05 Evaluate, then run supervised cases
Request 20 consecutive historical cases: ten for development and ten held out. Add separate stress cases.
Compare the current process, a capable model with the same records and tools, and that model with your
decision logic. Review expected decisions independently.

06 Earn renewal, then a second customer
Present results and an ongoing price. Continue when the manager pays again and delivery economics make
sense. Then sell the same workflow to a second independent operator, preferably on the same software and in
a similar legal regime.
Measure reused logic, evaluations, integrations, and onboarding effort. Expand one dimension at a time. If
existing software solves the problem, configure it; if the model-only version performs equally well, simplify.

Now Make the first three moves
1. Align roles. Owen leads product, implementation, evaluation, and the commercial decision. Connor leads
introductions, operational walkthroughs, and partner follow-through. Both attend the first calls.
2. Create one shared prospect list. Company, contact, introduction route, software, relevant workflow, and
next action.
3. Arrange the first three walkthroughs. Ask to see an ordinary case in the current system. Do not prepare a
product demo first.
