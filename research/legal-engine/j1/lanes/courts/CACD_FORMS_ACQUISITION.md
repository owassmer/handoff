# CACD forms acquisition reconciliation — October 1, 2026

`cacd_forms_addition.json` proposes CA:CACD-FORMS: 95 document targets, 45 specific exclusion/alternate-format decisions and 12 national/state cross-register dependencies. `cacd_inventory_rows.json` preserves the union of observed current official index rows. `build_cacd_forms.py` regenerates the proposal; no shared register was edited.

## Supported transport

The actual public storage route is `https://apps.cacd.uscourts.gov/cm-api/dwwwroot/`, with the exact publisher filename (including spaces and varying zero-padding). Discovery came from a current court-issued docket entry naming CV-011D's full URL, followed by successful retrieval of that official PDF. Independent official indexed packets also exposed this directory. This is evidence for a file store, not a guessed API endpoint. No authentication, court contact or case filing was performed.

Each selected filename was taken from the court's current public index, then tested at that store. Ninety-one selected PDFs resolved there. Two more—AO-0436 audio-recording order and G-101 ORDER student-practice order—resolved at actual independently indexed official legacy URLs. Thus 93 of the 95 selected targets returned actual official application/pdf documents. The earlier JS shell, failed guessed media/form routes, unavailable shell DNS and Chrome launch failure no longer control acquisition of those 93 documents.

The two exceptions remain explicit: G-002 sealed-case cover sheet (publisher January 2005) and CV-059 bill of costs (publisher January 2024, actual filename CV-59.docx). Their index identities and dates are established. Their dwwwroot references are a mapping from the demonstrated store plus published filename, not observed download hrefs or verified responses. Web retrieval returned internal errors without a dispositive HTTP cause. CV-059 is native Word, for which the existing generic acquisition route uses textutil after successful binary download; the web reader's error does not prove that file is absent. J2 must fetch these two, validate identity/edition and record the actual transport. If the mapped URL fails in a network-capable environment, use the rendered official form index's own download link. Do not save the JS shell as form text or invent another API.
