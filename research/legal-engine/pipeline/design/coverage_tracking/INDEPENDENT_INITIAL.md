# Initial independent challenge — durable coverage tracking

2026-10-01. Separate reviewer. Read the Goal 4 user objective and local GOAL.md, the parent’s proposed design, existing pipeline core/check/registercheck/CLI, prepared-task README and coverage review, and the previous completed collection-dependency research. No author implementation files changed. This is a design review, not implementation acceptance; implementation and fresh substantive demonstration still require inspection.

The proposed division is sound: agents investigate and defend conclusions, Jev contributes prepared atomic observations, and code preserves identities and checks recorded closure. Immutable revisions, expected-revision rejection and computed closure directly address interruption and premature completion. The following contracts need to be explicit and exercised before acceptance.

## Material concerns

1. **A reachable graph can become complete by losing its unfinished roots or edges.** Snapshot history alone does not prevent silent scope reduction. Preserve stable scope identity, exact original/current roots and boundary selectors, and explain each removal or replacement. An open item must not disappear merely because a new snapshot omits it. A shrink, source removal, changed selector or removed consequential edge must invalidate affected reviews and require independent review of the changed scope/exclusion. A deliberately narrower scope can be legitimate, but its status must identify that narrower claim rather than inherit the previous scope’s completion claim.

2. **A boundary cannot prove itself by comparing two copies of the same selected list.** Bind authoritative inventory evidence, exact enumeration/selection method, expected IDs, jurisdiction/unit/temporal boundary and independent enumeration review. Reconcile both directions: expected-but-unregistered and registered-selected-but-unexpected. Count equality is insufficient. Existing registercheck `[1]` compares counts and internal membership, not an independently established complete source universe. A replaced source preserving the count must fail reconciliation. Boundary evidence must cover the asserted universe; a chapter table of contents does not establish complete case-law or municipal-ordinance discovery. Unknown external targets and broad legal leads need explicit work items even before they have canonical section IDs.

3. **Content freshness is not current-law freshness.** Saved-byte hashes detect local change; they cannot detect an uncaptured amendment. Record the legal as-of date/event interval, version identity, effective/operative/repeal bounds, retrieval observation and the inventory/amendment evidence used to select that version. A later as-of date cannot silently inherit currentness from an older snapshot. Multiple versions of one section must coexist when an operating interval spans them. The just-completed CCP 1161 fee research is a concrete test: the current version starts February 1, 2025, while the predecessor already carried the fee ban in January. The tracker should expose missing predecessor coverage, not merely verify the current text hash.

4. **Cyclic dependencies must neither self-approve nor make review impossible.** Legal definitions can legitimately refer to each other. Compute a canonical finite reachable content graph with visited-node handling (or strongly connected groups). Bind review to node/edge/version/conclusion/evidence content, excluding review records themselves from the target digest; otherwise mutual reviews produce a recursive hash problem. Every consequential reachable item still needs a supported conclusion/exclusion and valid independent review. A cycle of resolved labels alone proves nothing. Unknown targets must block closure, never disappear from traversal.

5. **Reviews need exact scope and ongoing invalidation.** A review must state whether it covers enumeration, substantive interpretation, or integration; those are not interchangeable. A downstream change must invalidate upstream acceptance even if the upstream conclusion text remains identical. Bind the target’s transitive dependencies and actual evidence bytes, not only artifact filenames, report titles or review IDs. Review of a narrow passage cannot automatically cover an entire source or operating decision. The code can reject equal recorded author/reviewer identities and stale content, but must not claim to authenticate real independence or certify legal sufficiency from a hash or nonempty paragraph.

6. **Interrupted writes require a concrete commit and recovery protocol.** Expected revision must be checked while holding the exclusive writer lock. Write/fsync a complete uniquely named immutable revision, then atomically replace/fsync the current pointer; readers see the old or new valid snapshot. An orphan revision after a crash must not be silently promoted. Missing/corrupt pointers or mismatched revision identities fail visibly; do not quietly roll back and present stale closure as current. Specify lock lifetime/recovery so a killed process does not permanently prevent progress or let a live writer’s lock be stolen. Preserve earlier revisions rather than rewriting them during recovery. State whether the guarantee is process interruption or power-loss durability; atomic rename alone does not establish the latter.

7. **External files and integrations can change outside the tracker lock.** Register selections, source bodies and prepared follow-ups must be bound to exact bytes and revalidated when computing status, including after updates. A tracker lock does not lock those existing files. Avoid reading a selection from one version and binding a later version’s hash. Treat the computed status as a report for a particular revision and external-evidence observation, not a perpetual authorization. Imports should preserve source identity, exact occurrence, unknown target, model preparation and existing next action. A successful fetch, Jev negative, legacy `no_decision`, match result, or completed project heading must not become substantive closure automatically.

8. **Existing completion surfaces can bypass the new meaning.** Existing `check.py` J2 means downloaded text; J4 accepts match/reviewer decisions; J8 checks only critical findings in the latest review; J9 checks an accepted profile and stored hashes. None currently establishes this proposed research closure. Add an explicit integrated coverage report/gate or make the separation unambiguous in the existing overall check output and relevant execution path. A separate new command alone is insufficient if the old aggregate output is still described as confirming complete coverage. Preserve historical artifacts and legitimate legacy behavior, but do not let old labels grant new closure. Do not feed context-sensitive reasoned interpretations through the existing blanket hedge-word ban merely to obtain mechanical acceptance.

## Required observable challenge cases

| Challenge | Expected behavior |
|---|---|
| Inventory expects A/B/C; register has A/B/D | Both C missing and D unexpected visible despite equal counts; closure blocked. |
| Remove an unresolved item, root, selected source or dependency edge | Explicit scope-change/exclusion trail and fresh applicable review required; prior closure not reused. |
| External statutory reference has no resolved identifier; source says “other applicable law” | Work remains visible with affected decisions and concrete investigative next action. |
| A depends on B depends on changed C | A/B acceptance stale even when A/B own prose is unchanged. |
| A↔B cycle with one unsupported conclusion | Terminates deterministically and blocks closure; resolving/reviewing the finite group can later succeed. |
| Current source text unchanged but declared legal interval adds an earlier/later edition | Version/applicability investigation required; byte equality alone does not close it. |
| Review artifact, source bytes, selector, boundary evidence or author changes | Affected acceptance becomes stale or invalid. |
| Two writers start from revision N | Exactly one N→N+1 commit succeeds; the other gets an explicit revision conflict without lost work. |
| Process exits before revision write, after revision write, or around pointer replacement | Resume yields one complete valid current revision; prior history preserved; orphan state explicit. |
| Register/follow-up changes after import | Current status exposes mismatch/new work; it does not rely on the original import’s success. |
| Legacy/model negative or successful retrieval imported | Retained as evidence/history with open substantive work, never automatic reviewed closure. |
| Goal 3 report imported | Exact accepted report/review bindings and remaining factual conditions preserved; broad California inventory not marked complete. |

The fresh demonstration should include an actual operating decision, source boundary evidence, at least one consequential dependency discovered during investigation, an interrupted/resumed update, a supported final conclusion and independently challenged enumeration/meaning. Authored adversarial fixtures are useful tests, but cannot substitute for that substantive demonstration. A deliberately bounded completed example should coexist with clearly open larger coverage.

Initial conclusion: proceed with implementation subject to these explicit contracts. No implementation or whole-goal acceptance is granted by this report.
